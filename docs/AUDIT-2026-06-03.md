### MITRE ATLAS remap (4 wrong mappings corrected; 15 techniques)
The suite cited the legacy ML-attack matrix with four substantive errors:

| Cited | Was labeled | Correct (current ATLAS) |
|---|---|---|
| AML.T0046 | "Unsafe ML Inference" | Spamming AI System with Chaff Data |
| AML.T0018 | "Persistence" | Manipulate AI Model |
| AML.T0056 | "MCP Compromise" | Extract LLM System Prompt |
| AML.TA0006 | "Defense Response" (as a technique) | Persistence (this is a *tactic*, TA-prefix) |

Every scenario was remapped to the current matrix — 15 techniques, including the AI-agent technique family added in 2025 (T0050, T0105, T0034.002, T0025, T0055, T0037, T0081, T0051, T0054, T0057, T0053, T0073, T0086, T0046, T0015). See [mitre-atlas-mapping.md](mitre-atlas-mapping.md).

Defensive-response tests (enforcement, kill-switch) and detection-capability tests (intelligence layers, correlation, baseline) are **no longer mapped to adversary techniques** — ATLAS is an adversary framework, and the old "TA0006 Defense Response" mapping conflated the attacker matrix with the defender.

### Scoring-engine correctness (`src/benchmark/scoring.ts`)
This is the leaderboard/tier path a vendor uses to self-score (it is **not** the path that produced the published corpus numbers — those come from `scripts/run-benchmark-v2.ts`, which computes a correct pooled confusion matrix).

- **FPR was macro-averaged across 9 categories**, diluting it ~9×. A scanner that flagged every benign artifact could report a single-digit FPR and reach "gold". Now computed from a single pooled benign confusion matrix.
- **Category-agnostic detectors were scored as false negatives**: a correct `malicious` verdict with no `category` field scored as a miss. Recall is now credited on the verdict; category is a secondary attribution.
- **The reference baseline was order-dependent** for Cohen's Kappa. It is now frozen before any adapter is scored, and the baseline is flagged (`isHMABaseline`).
- Added 3 regression tests covering the above.

### OWASP mapping corrected to LLM Top 10 (2025)
Data exfiltration was mislabeled "System Prompt Leakage" (LLM07); it is Sensitive Information Disclosure (LLM02). IDs now follow the published 2025 list in [owasp-agentic-mapping.md](owasp-agentic-mapping.md).

### Capability gating (`describeWithCapability`)
The "N/A not FAIL" helper existed but was wired into no test. It is now wired into the five AI-layer suites, so a product that does not declare a surface reports N/A instead of FAIL. Verified: under `OASB_ADAPTER=llm-guard`, the MCP/A2A/output AI-layer suites correctly skip.

## Open follow-ups

These are tracked, lower-severity items, safe to address in a later pass:

1. **OS-level capability gating.** Gating is wired for the AI-layer surface only. The process/network/filesystem/enforcement suites are not yet gated, so a prompt-only product (e.g. `llm-guard`) still reports failures there rather than N/A. Wiring the remaining suites is mechanical but touches ~30 files.

2. **Atomic AI-layer tests assert the reference adapter's pattern IDs** (e.g. `PI-001`). They verify conformance to the OASB harness, not neutral detection quality. Cross-product *detection* comparison belongs in the verdict-based Scanner Benchmark (corpus) track. Consider splitting "harness conformance" from "detection" assertions.

3. **`disqualified` tier is defined but never assigned.** `TIER_THRESHOLDS.disqualified` exists with no code path that returns it. Either add a disqualification rule (e.g. no results submitted, or FPR above a hard ceiling) or remove the unused tier.

4. **`requireCapability()` is a documented no-op.** `describeWithCapability()` is the working path; `requireCapability()` should either be implemented or removed to avoid a misleading export.

5. **Adapter category disagreement.** `hma-real-adapter` maps the `exfiltration` class to `credential_exfiltration` while `hma-pipeline-adapter` maps it to `data_exfiltration`, producing inconsistent per-category breakdowns across the two HMA pipelines.

6. **`categoryCoverage` denominator is dynamic** (categories present in the dataset) while tier thresholds are fixed (9/7/5). Tiers assume the canonical full 9-category dataset; a partial dataset silently caps coverage. Documented in `scoring.ts`; consider a proportional threshold if partial-dataset runs become common.

7. **Latency percentiles are conditional on detection** (`metrics.ts` computes mean/P95 over detected attacks only). Defensible by design; worth a doc note so the field is not read as all-attack latency.
